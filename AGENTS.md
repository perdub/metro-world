# Базовые правила разработки Minecraft-модов

Предпочтения пользователя, согласованные 5 октября 2026 года. Применять к следующим Minecraft-модам, пока пользователь не задаст другие условия.

- Целевая версия по умолчанию: Minecraft 1.21.1, Fabric, Java 21. Для серверных модов использовать Polymer, когда он позволяет работать без обязательного клиентского мода.
- Репозиторий должен содержать Gradle Wrapper, CI/CD, Dockerfile, Compose, пример настроек и краткую инструкцию запуска.
- В CI запускать Gradle через `bash ./gradlew --no-daemon test build`, чтобы ZIP/Windows не ломали запуск потерей executable-бита.
- Серверный контейнер строить на `itzg/minecraft-server:java21`, задавать Minecraft/Fabric явно и включать собранный мод, Fabric API и совместимые серверные оптимизации. Текущий базовый набор: Lithium, FerriteCore, Krypton.
- По умолчанию `EULA=TRUE`, **`ONLINE_MODE=FALSE`**. Пользователь отдельно исправил первоначальное TRUE на FALSE.
- Внутри контейнера Minecraft слушает TCP 25565. Compose публикует его на настраиваемый внешний порт, по умолчанию 25565; при необходимости пользователь может выбрать 80. RCON не публиковать наружу по умолчанию. Для CI использовать свободный порт только на 127.0.0.1.
- До публикации обязательно запускать контейнер с временным миром. Проверять успешный старт, установленные моды, EULA, offline mode, доступность Minecraft-порта и серверные функции мода. Для модов с измерениями проверять измерение и генерацию чанков.
- При ошибке проверки сохранять серверные логи как артефакт и блокировать публикацию образа. Удалять временные контейнеры и тома после проверки.
- После проверки публиковать именно проверенный образ: `dev-latest` для основной ветки и обычную версию для тега `v*`. Сохранять JAR и контейнерный архив `docker save` как CI-артефакты.
- Проверять совместимость сторонних модов с точной версией Minecraft и загрузчиком, проверять контрольные суммы, сохранять манифест версий образа.
- Пользователю отдавать полный ZIP корня репозитория: файлы сразу в корне архива, включая `.github` и `.env.example`. Не включать `.git`, кэши, временные миры, секреты и локальный `.env`.
- При изменении имён/удалении файлов явно сообщать, какие старые файлы удалить. Не удалять пользовательские миры при обычном обновлении контейнера.
- Не заявлять, что Minecraft или контейнер проверены, если запуск недоступен. Указывать, что проверено локально, а что должен выполнить CI.
