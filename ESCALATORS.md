# Эскалаторы

`/metro-escalator build <rise> up|down north|south|east|west` — команда оператора. Начало располагается в трёх блоках от игрока, выбранное направление всегда указывает **в сторону верхней площадки**, включая `down`. Подъём 1–32 блока, горизонтальный пробег вдвое длиннее. Нужна незанятая сухая полоса шириной пять блоков и свободное пространство над ступенями. Строитель проверяет весь объём перед изменениями, не выкапывает тоннель через существующие блоки.

Ступени — обычные ванильные полублоки и полные блоки, поэтому по ним можно идти самостоятельно без клиентского мода. Посадочные маркеры — Polymer-блок с ванильным видом жёлтого бетона. Над неподвижными ступенями движутся тонкие полосы BlockDisplay: циклическое движение соответствует направлению переноса. Анимация работает возле игроков, одновременно максимум у четырёх эскалаторов и до 32 полос на каждом. Полосы не имеют столкновений, пол остаётся настоящим ванильным. Движение стоящего игрока реализовано серверными переносами по 0,08 блока за тик. Это экспериментальная имитация: возможны рывки при задержке сети и конфликт с античитом. Прыжок, приседание, полёт, транспорт или уход в сторону прекращают перенос; после выхода на площадку активация заканчивается. Перед каждым перемещением проверяется опора и столкновения с окружающими блоками.

`/metro-escalator list` показывает число зарегистрированных конструкций. `/metro-escalator disable-nearest` прекращает движение ближайшего эскалатора в радиусе 64 блоков, оставляя обычную лестницу. В отдельном `metro-world-escalators.json` корня мира сохранены измерение, начало, ориентация, высота и направление движения каждой конструкции. Блоки сохраняются Minecraft отдельно как часть мира. Испорченный JSON не перезаписывается автоматически. Визуальные сущности очищаются при уходе игроков, сохранении и остановке. Сохранённые после аварии полосы удаляются при загрузке сущностей; обработчики ENTITY_LOAD/ENTITY_UNLOAD регистрируются самим initialize().

## Подключение

В `InfrastructureMod.onInitialize()` вызвать `Escalators.initialize()` после регистрации инфраструктурных блоков. При регистрации команд вызвать `Escalators.registerCommands(dispatcher)`.

Зарегистрировать `SERVER_STARTED -> Escalators.load(server)`, `END_SERVER_TICK -> Escalators.tick(server)` **каждый тик, до существующего ограничения в 20 тиков**, `SERVER_STOPPING -> Escalators.save(server)`, `SERVER_STOPPED -> Escalators.reset()`. Команды строительства и отключения дополнительно сохраняют изменения сразу.

API `Escalators.build(ServerWorld, EscalatorGeometry.Plan)` создаёт конструкцию и добавляет запись движения, возвращая false при занятом месте. После вызова из серверной логики сохранить `Escalators.save(server)`. `Plan(x,y,z,dx,dz,rise,descending)`: y — высота ног нижней площадки, ось dx/dz — единичное направление подъёма. Это API для готового свободного объёма, его нельзя вызывать прямо из асинхронного `NetworkBuilder`: worldgen должен подготовить лестничный объём, а серверная логика выполнить установку на основном потоке после генерации чанков. Автоматических эскалаторов в станциях пока нет.

Локальные проверки покрывают геометрию, направления и прекращение активации за площадками. Реальное движение, столкновения, сохранение/перезапуск и поведение клиента требуют Minecraft smoke test.

Для строителя и полос используется floorHeight(along) — высота настоящего пола в центре клетки. Для переноса height(along) учитывает передний край игрока шириной 0,6 блока: подъём начинается до пересечения центром границы ступени, чтобы модель не вошла в следующую ступень. В центре первой клетки обе высоты равны нижнему полублоку (y + 0,5).
